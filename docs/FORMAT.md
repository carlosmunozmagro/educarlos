# Content format

Two file kinds. `schema/*.schema.json` gives editor autocomplete;
`tools/validate.py` is what actually enforces the rules.

```
content/index.json                     { "courses": ["crypto-chains", ...] }
content/<course>/course.json           meta + chapter/lesson manifest
content/<course>/lessons/<id>.json     one lesson, one file
visuals/<course>/<name>.svg            referenced by path from a visual block
research/<course>/<id>.md              the sourced brief a lesson was written from
```

## course.json

| Field | |
|---|---|
| `id` | must equal the directory name |
| `lang` | `en` or `es` — drives the UI chrome language |
| `accent` | `#rrggbb`, the course's one accent colour |
| `title`, `subtitle` | library card |
| `description` | top of the course map |
| `needsSources` | `true` for law/tax/regulation. Forces sources + `reviewedOn` on every lesson |
| `disclaimer` | required when `needsSources` is true |
| `chapters[]` | `{ id, title, lessons: [{ id, title, summary }] }` |

A lesson listed in the manifest must have a matching file, or validation fails.

## lesson.json

`{ id, courseId, chapterId, title, reviewedOn, screens[] }`

`screens[]` → `{ kind?, blocks[] }`. `kind` is `"title"` on the opening screen only.
The closing "lesson complete" screen is generated by the app — do not author it.

## Blocks

| Type | Fields |
|---|---|
| `prose` | `eyebrow?`, `heading?`, `text[]` |
| `visual` | `src`, `alt`, `caption?` |
| `formula` | `tex`, `caption?` — KaTeX, display mode |
| `code` | `code`, `label?`, `lang?` |
| `table` | `columns[]`, `rows[][]`, `caption?` |
| `callout` | `text[]`, `tone?` (`key`\|`note`\|`warning`\|`gotcha`), `title?` |
| `steps` | `items[] = { title?, text }` |
| `reveal` | `question`, `answer[]` |
| `sources` | `items[] = { title, url?, note? }` |

## Inline markdown-lite

Valid in every text field: `**bold**`, `_italic_`, `` `code` ``, `[text](url)`, `$math$`.
Everything else is escaped. `$` must be balanced or validation fails.

## Enforced limits

- ≤ 80 words of prose per screen (`prose` + `callout` text combined)
- ≤ 1 visual per screen
- ≥ 3 screens per lesson
- table rows must match the column count
- `visual.src` must exist on disk
- `reviewedOn` is `YYYY-MM-DD`; older than a year raises a warning
